## 제안하는 방향

**‘관측자가 정답을 결정한다’보다 ‘내가 알아간 만큼 내 세계가 넓어진다’를 중심 문장으로 둡니다.** 사용자의 위로라는 목적을 살리면서도, 관측 전에는 실제 천체의 상태가 미정이고 사람의 인지가 그것을 결정한다는 식의 오해를 피할 수 있습니다. 거시적인 천체에는 주변 환경과의 상호작용이 계속 일어나며, 우주 전체에 고유한 중심도 없습니다. 여기서 중심은 **탐색 화면과 개인의 경험을 여는 위치**라는 은유입니다. [환경 상호작용에 따른 결잃음 실험](https://www.nature.com/articles/35002001), [NASA의 우주 중심 설명](https://science.nasa.gov/mission/webb/big-bang-q-and-a/).

현재 구현의 풍부한 하늘과 기능은 그대로 연결할 수 있도록 흐름만 다시 배열했습니다.

| 장면 | 지금보다 앞에 둘 것 | 뒤로 보낼 것 |
| --- | --- | --- |
| 첫 하늘 | 한 문장, 빛 하나를 고르는 행동 | 색인 수, 기능 모음, 거리 눈금 |
| 빛을 읽다 | 짧은 사실, 거리, 한 가지 다음 행동 | 긴 소개와 모든 근거의 동시 노출 |
| 내 세계 | 내가 알아간 빛과 가장 먼 거리 | 상세 비교와 전체 기록 |

‘내 세계’ 지도에서는 **알아간 천체를 살구색으로 채운 표식과 이름표, 나에게 이어지는 실선**으로 표시합니다. 아직 만나지 않은 천체는 작은 빈 점과 점선 윤곽으로 남깁니다. 현재 선택한 천체에는 표식 둘레에 흰 고리를 더합니다. 색을 보지 못하더라도 채움·윤곽·선·이름표로 상태를 구별할 수 있도록 한 시안입니다. 실제 앱에 적용할 때는 이 표식을 3D 하늘, 검색 결과, 천체 서랍에서도 똑같이 쓰고, 천체를 담거나 지우면 모든 화면의 상태를 함께 갱신합니다.

프롤로그는 현재 경험이 잘 맞으므로 구조를 유지하고, 마지막 장면에서 시안의 첫 하늘로 부드럽게 이어지는 방식이 좋습니다. 답변과 근거는 항상 접근 가능하게 두되, 읽기의 첫 단에는 검증된 핵심 사실 하나만 보여 주는 방식입니다.

## 첨부 이미지에서 가져온 시각 언어

- 밤하늘: 남보라 `#222454` → 흐린 보라 `#9970AF` → 푸른빛 `#63A9C9`
- 안심의 여백: 살구 `#F3DAD5`, 종이 `#FFFAF5`
- 별: 큰 광원 몇 개와 미세한 점 다수. 정보나 버튼의 광채는 절제합니다.
- 제목: 명조, 짧고 느린 호흡. 설명과 근거: 간결한 고딕.

첨부 이미지는 색감과 여백의 **참고**로만 사용했습니다. 원본 포스터의 문구, 구도, 그래픽을 제품 화면에 복제하지 않았습니다.

## 참고할 실제 사례

- [NASA Exoplanet Travel Bureau](https://science.nasa.gov/exoplanets/immersive/exoplanet-travel-bureau/) — 낯선 우주 정보를 ‘떠나 보고 싶은 장소’의 감정으로 번역하는 편집 방식. 포스터를 베끼기보다 천체마다 하나의 강한 문장을 고르는 방식이 유용합니다.
- [NASA Eyes](https://www.nasa.gov/interactives/) — 탐색할 수 있는 3D 우주. 현재 프로젝트의 실제 하늘 깊이를 유지할 때 참고할 상호작용 사례입니다.
- [Stellarium Web](https://stellarium-labs.com/stellarium-web/) — 실제 하늘 위에 선택 가능한 천체를 놓는 정보 구조. 이 시안은 그 진입을 좀 더 조용하고 감정적으로 만듭니다.
- [NASA Observable Universe](https://science.nasa.gov/image-article/apod-2022-march-16-the-observable-universe/) — 관측 가능한 우주를 관측자의 자리에서 보여 주는 거리 표현의 참고 자료입니다.

## 구현 시 우선순위

1. 기존 3D 하늘 위 UI만 재배치하여 첫 화면의 시선 경로를 단순화합니다.
2. 천체 서랍의 첫 단을 ‘한 가지 사실 → 출처 → 더 묻기’로 정리합니다.
3. ‘내 세계’는 알아간 점과 한 문장 요약부터 보여 주고, 비교와 기록은 펼치게 합니다.
4. 태블릿과 휴대폰에서는 3D 하늘의 정보 밀도를 낮추고 읽기 카드를 화면 하단으로 보냅니다.

이 시안은 디자인 논의를 위한 정적 프로토타입입니다. 실제 앱에 반영할 때에는 기존 RAG 답변, 출처 표시, 안전 안내, 실측 하늘 기능을 그대로 이어야 합니다.
